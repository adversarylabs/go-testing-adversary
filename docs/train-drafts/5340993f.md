## What we want to improve

Report added or modified functions in changed files that accept *testing.T or *testing.B and call testing failure or reporting APIs but do not invoke the testing object's Helper method.

## Why this matters

When a helper that reports test failures does not mark itself as a helper, failure output points to the helper implementation instead of the test call site, making debugging and triage harder.

## Examples

- A web-server test adds an assert helper that accepts *testing.T and calls Fatalf on mismatch but does not call the testing object's Helper method, causing failures to point into the helper.
- A database client test introduces a convenience function taking *testing.T that invokes Errorf on assertion failures but omits calling the Helper method, so failing cases report the helper's line.
- A benchmark for an image-processing library moves common checks into a helper accepting *testing.B which calls Fatal on invalid state without calling Helper, hiding the benchmark call site in failure output.

## Keep it focused

- A changed helper that accepts *testing.T but performs validation and returns an error without calling testing failure methods should not be flagged.
- A helper that intentionally reports diagnostics at its own implementation lines, for example by using runtime caller information, and therefore omits calling the testing object's Helper method should not be flagged.
